# Simulated Ingest — ids-core

## Purpose

The simulated ingest provides controlled synthetic event generation for development, testing, and demonstration of the `ids-app` platform. It allows generating realistic IT and OT security events without requiring real network traffic or sensors.

## Design

```
POST /api/v1/simulate/events → Simulator → EventStore (memory)
                                                ↓
                                       GET /api/v1/events/recent
```

Events are generated by the `Simulator` based on predefined `Scenario` templates. Generated events are stored in an in-memory `EventStore` for API retrieval.

## Scenarios

| Scenario | Description | Severity | Zone | Protocol |
|----------|-------------|----------|------|----------|
| `normal_it_connection` | Standard HTTPS/DNS outbound | info/low | it | https, dns, http |
| `ot_modbus_read` | Modbus read from OT | low/medium | ot | modbus |
| `ot_s7_command` | S7 PLC command | medium/high | ot | s7comm |
| `scan_detected` | Port scan from external | high | dmz | tcp |
| `auth_failure` | Auth failure from external | medium | dmz | ssh, rdp, smb |
| `protocol_anomaly` | OT protocol anomaly | high/critical | ot | modbus, s7comm, profinet |
| `malware_indicator` | Malware/IoC detected | high/critical | it | http |

## Endpoints

### GET /api/v1/events/recent

Returns recent events from the in-memory store.

**Query parameters:**
- `limit` (optional, default: 50, max: 500)

**Response:**
```json
{
  "items": [...],
  "count": 2,
  "limit": 50
}
```

### POST /api/v1/simulate/events

Generates simulated events.

**Request body:**
```json
{
  "scenario": "scan_detected",
  "count": 2
}
```

**Fields:**
- `scenario` (required): one of the 7 valid scenarios
- `count` (optional, default: 1, min: 1, max: 100)

**Response:**
```json
{
  "items": [...],
  "count": 2,
  "scenario": "scan_detected"
}
```

## Limits

- EventStore holds max 5000 events (configurable)
- Events older than the max are evicted (FIFO)
- API returns max 500 events per request
- Simulator generates max 100 events per batch

## Why Simulated?

- No PCAPs, no real traffic, no sensors required
- Events are fully valid and pass domain model validation
- Enables development of dashboard, analytics, and MCP without network infrastructure
- Future: replace with real sensor ingest (Suricata, Zeek) while keeping the same event model
